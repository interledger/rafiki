*** HISTORICAL RECORD — DO NOT USE AS A THROUGHPUT BASELINE ***

This run used vus: 1. With a single virtual user the "Iterations/s" figure
below is arithmetically just 1000 / iteration_duration_ms (109.79ms -> 9.11),
so it measures SERIAL LATENCY, not throughput, and cannot show a concurrency
or batching improvement. Measured capacity on the same build was roughly 2.5x
this number.

Note also that this run predates the addition of a 4th mutation
(depositOutgoingPaymentLiquidity) to the script, so it is 3 requests per
iteration where later runs are 4. Comparing it directly against a later run
produces a phantom regression.

Superseded by test/performance/bench.sh + outgoing-payments-bench.js.
See performance-improvement.md sections 1 and 2.
